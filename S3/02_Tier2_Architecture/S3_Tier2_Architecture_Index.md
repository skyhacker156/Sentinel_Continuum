S³ Tier-2 Architecture Index

This file defines and governs all architectural files inside Tier-2.

Tier-2 is the layer that describes how the Sentinel Continuum is arranged — the structural scaffolding that supports all doctrine and protects the sealed engine.

The index is required for:

architectural clarity

LLM alignment

containment enforcement

cross-model consistency

prevention of drift

proper routing

This file is canonical — all future Tier-2 documents attach to it.

I. Directory Purpose

Tier-2 describes:

the Continuum structural layers

the relationship between layers

conceptual system diagrams

non-enabling architecture

permission boundaries

routing rules

governance rails

Tier-2 does not contain:

algorithms

code

parameters

thresholds

reconstructable details

sealed mechanics

This is structure only.

II. Required Tier-2 File Classes

All Tier-2 documents must fall into one of the following categories:

1. Structural Schematics

Non-enabling conceptual diagrams or textual layouts of:

Continuum tiers

Vault / Crypt / Cathedral architecture

Public-safe data flows

Role and permission layers

2. Routing & Governance Files

Includes:

LLM interaction rules

containment boundaries for Tier-2

drift detection processes

file naming conventions

update propagation rules

3. Architectural Frameworks

Conceptual frameworks describing:

separation of concerns

vertical layer integration

system identity rules

high-level operational scaffolding

4. Non-Enabling API Descriptions

High-level text describing:

permitted inputs

expected outputs

conceptual interfaces

role boundaries

These are conceptual only — never executable, never revealing.

III. Forbidden Material

The following is prohibited in Tier-2:

executable code

implementation details

S³ internals

numerical thresholds

reverse-engineerable logic

transformer-like descriptions

microstructure reconstruction pathways

descriptions of Tier-3 or Tier-4 operations

Violation triggers Containment Doctrine.
