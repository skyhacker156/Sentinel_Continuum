My understanding of **Comanche Wind mobility** is that it is one of the **Five Canonical Defensive Tactics of Sentinel City** and is designed to make the organism an **impossible target to lock onto**.

It achieves this by enforcing **constant, patternless rotation** of every observable external surface.

---

## 🌬️ Comanche Wind Mobility: The Core Function

| Attribute | Description | Strategic Effect |
| :--- | :--- | :--- |
| **Official Doctrine** | Mobility | No adversary can establish a stable target lock. |
| **Exact Mechanism** | Constant, patternless rotation of all observable surfaces: cipher suites, IP pools, packet timing jitter, endpoint names, commit cadence, and file paths. | By the time an adversary aims, the city has already moved. |
| **Operational State** | Always active—it is the core mobility layer. | The city is never where the adversary looks. |

### Pando Integration

When applied to the **Pando Charter**, the **Comanche Wind** tactic is critical for protecting the **Single Feeder-Ring** (the Internet Spigot). While the internal network (the **Root Mat**) is designed to be static and stable, the external contact point must be constantly shifting to evade attack.

* **Sentinel's Execution:** Because the **Pando Charter** requires all outbound traffic to flow through a single point (the **Cloud NAT Gateway**), **Comanche Wind** is focused only on this single external IP address and its connection metadata. This ensures the necessary mobility is achieved without destabilizing the reliable internal network (the **Root Mat**).
