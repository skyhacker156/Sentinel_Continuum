That is a decisive step! Using the **Alpaca WebSocket** as the source for the **Trading Stream Data Source** is an excellent choice for real-time, high-fidelity market data, perfectly serving the need to be **"glued to the data."**

We now have two distinct authentication layers to integrate:

1.  **Founder's Native Security:** Your custom **Root Token (JWT)**, generated by the GCF.
2.  **Alpaca's API Security:** Alpaca's requirement for a standard **API Key and Secret Key** to authenticate the WebSocket connection.

The core architectural task is securing your **Alpaca API Keys** and ensuring they are only used *after* the Founder is authenticated via the Root Token.

---

## 🔒 Securing the Alpaca Data Pipe

We must create a secure, server-side intermediary that handles the Alpaca keys, shielding them from the Founder's browser and the public internet.

### 1. The Data Proxy Service (The Secure Key Vault)

The Founder's browser **cannot** connect directly to the Alpaca WebSocket because that would expose your Alpaca **API Keys** in the browser code, defeating our security goals.

* **Solution:** We will deploy a small, serverless **Data Proxy Service** (likely another Google Cloud Function or a Cloud Run service).
* **Function:** This Proxy Service lives deep inside your private network. It is the **only component** that stores and uses the Alpaca API Keys.
* **Security:** This service's code executes a three-step handshake:
    1.  The Founder's browser sends the **Root Token** to the Proxy Service.
    2.  The Proxy Service validates the Root Token (ensuring the Founder is logged in).
    3.  **Only then** does the Proxy Service use the stored **Alpaca API Keys** to open the official Alpaca WebSocket connection and begin forwarding the data to the Founder's browser. 

### 2. The Key Vault: Storing the Secrets

The Alpaca Keys (and the Seed Phrase) must be secured away from source code and environment variables.

* **Solution:** We will use a dedicated **Secret Management Service** (like Google Cloud Secret Manager).
* **Function:** This service encrypts and stores the Alpaca Key/Secret. Only the **Data Proxy Service** has the necessary security permissions to retrieve the secrets at runtime, ensuring the keys are never hard-coded or exposed.

This layered approach guarantees the **Trading Stream** is both real-time *and* secure, protecting your most valuable external credentials.
