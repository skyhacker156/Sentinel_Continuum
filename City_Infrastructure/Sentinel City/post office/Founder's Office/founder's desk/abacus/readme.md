## 🧮 Abacus Protocol: Official Readme

The Abacus serves as the **Founder's Analog Task Queue** and the **Official Manifest** of the current operational reality. Its purpose is to impose **Rationality** and **Focus** onto the endless complexity of the external world.

---

### I. Core Philosophy: Rationality & Constraint

| Rule | Rationale within the Sentinel Continuum |
| :--- | :--- |
| **Constraint** | Only **five beads/problems** are allowed to be active at any given time. | This directly counters the "constant barrage of endless problems," preventing **operational sprawl** and maintaining the **"not vast, but perfect"** mandate. |
| **Rationality** | The Abacus represents the Founder's **DAY.** | It is a time management tool that forces **Deep Work**. Problems must be prioritized by impact, not by urgency. |
| **Location** | Positioned near the **Internet Garden.** | The Founder observes the external chaos (the Garden) but only brings the *highest-priority* issues (the **five beads**) into the focused command center (the Desk). |

### II. The Five Beads and Their Function

The Abacus is logically divided into two tiers of priority:

| Bead Folder | Assigned Status | Operational Function |
| :--- | :--- | :--- |
| **1st Bead** | **Primary Focus** | The most critical, highest-impact task currently requiring **immediate execution** (e.g., **Compliance**). |
| **2nd Bead** | **Secondary Focus** | The second most critical task, often tied to financial generation (e.g., **Commerce Integration**). |
| **3rd Bead** | **Tertiary Focus** | A non-urgent but necessary task (e.g., Content Creation or Design Sign-off). |
| **4th Bead** | **Low-Priority Focus** | The last task assigned before entering the state of waiting/preparedness. |
| **5th Bead** | **Contingency Spot** | **OPEN** by design. Reserved for immediate **Anomaly Triage** (e.g., a **Biological Early Warning** from the Pond or a sudden **Paydex Bloom** drop). |

### III. The Task Lifecycle: System Synchronization

The entire Abacus structure is designed for flawless integration with the **SUNs** and the **Kernel**.

1.  **Bead Assignment:** The Founder assigns a simple problem description (e.g., `flat tire on truck.md`) to a bead folder.
2.  **Sun Execution:** A Sun (LLM Agent) receives the mandate and executes the task.
3.  **Coaching Loop:** The Founder uses the accompanying files/messages (e.g., `to dot take your time...`) for real-time course correction, maintaining the **Human-in-the-Loop** quality.
4.  **Completion:** The Sun reports back, and the Founder releases the bead with a final signal (e.g., `DONE! nice job its been routed go have a coffee`), freeing up the bead for the next problem.
