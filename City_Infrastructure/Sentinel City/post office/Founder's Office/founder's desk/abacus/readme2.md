# 🧮 Abacus Protocol

The **Abacus** is the Founder's bounded task system used to organize the operational day.

It limits the number of active problems and enforces disciplined focus.

Only a small number of problems may exist simultaneously.

---

# Core Principle

The Abacus represents **the current operational reality**.

External issues exist in the world, but they only become active when placed onto a bead.

This prevents operational sprawl and maintains clarity.

---

# Structure

The Abacus contains **five beads (task slots)**.

| Bead         | Function                                   |
| ------------ | ------------------------------------------ |
| **1st Bead** | Primary task requiring immediate attention |
| **2nd Bead** | Secondary task                             |
| **3rd Bead** | Necessary but non-urgent work              |
| **4th Bead** | Low-priority task                          |
| **5th Bead** | Contingency slot for unexpected issues     |

The **fifth bead remains open when possible** to handle new problems.

---

# Rules

1. No more than **five active problems**.
2. Tasks are ordered by **impact**, not urgency.
3. Only problems placed on beads are considered **active work**.

---

# Task Lifecycle

```
Assign Problem → Work → Complete → Release Bead
```

Once completed, the bead becomes available for the next task.

---

# Model

```
Abacus

[1] Primary
[2] Secondary

```

The Abacus acts as the **Founder's daily command board**.
